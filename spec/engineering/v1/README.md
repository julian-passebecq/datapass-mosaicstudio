# `datapass.engineering/1` — engineering sidecar contract (frozen)

Status: **frozen**. A change to any rule, key, code or canonical form is a new version (`datapass.engineering/2`), never an
edit of this one. Consumers pin it at a commit (see [Vendoring](#vendoring)).

| Piece | Where |
|---|---|
| Source of truth (types, `validateEngineering`, `canonicalJson`, `digest`, `engineeringSchema`) | `src/framework/engineering/contract.ts` (self-contained: no imports) |
| Python mirror (standard library only) | `py/datapass_engineering.py` |
| JSON Schema 2020-12 (structure only), generated by `npm run contracts` | `spec/engineering/v1/engineering.schema.json` |
| Conformance corpus (records, c14n vectors, legacy 0.8.1 artifact) | `tests/fixtures/engineering/` + `manifest.json`, generated by `scripts/make-engineering-corpus.mjs` |
| Tests (TypeScript and Python must reach identical decisions and identical bytes) | `npm run test:engineering-corpus` |
| Diagnostic codes `DP-ENG-001..016` | `docs/DIAGNOSTIC_CODES.md` |

The sidecar **references** existing records; it changes none of them. `datapass.artifact/1`, `datapass.runtime/1` and
`datapass.bundle` v1 are read and written exactly as before.

## Envelope

Every record is one JSON object, at most 1 MiB of UTF-8 and 32 levels deep:

```json
{"format": "datapass.engineering", "version": 1, "kind": "<kind>", ...}
```

Unknown `format`, `version`, `kind` or any key a kind does not define is refused. Rules run in a fixed order and the first
refusal wins, with the same `DP-ENG` code and the same JSON-pointer `where` in TypeScript and Python.

## Digests

A digest always names what it covers:

```json
{"alg": "sha256", "over": "bytes" | "datapass-c14n/1", "value": "<64 lowercase hex>"}
```

- `over: "bytes"`: SHA-256 of the exact bytes as stored or transmitted (files, artifacts). Never re-serialize to hash.
- `over: "datapass-c14n/1"`: SHA-256 of the UTF-8 bytes of the canonical JSON below (structured payloads: inputs,
  proposals, design revisions).
- `artifact-ref.sha256` is always over the exact bytes (same meaning as `artifactSha256` in runtime/1).

### `datapass-c14n/1`

RFC 8785 JSON Canonicalization Scheme (JCS):

- object keys sorted by **UTF-16 code units** (so U+1F600 sorts before U+FB01), no whitespace;
- strings: only `"`, `\` and U+0000..U+001F are escaped (`\b \t \n \f \r`, otherwise lower-case `\u00xx`); everything
  else, U+2028 and DEL included, is written as UTF-8;
- numbers: IEEE-754 doubles written as ECMAScript `Number.prototype.toString` writes them (`1.0` → `1`, `-0` → `0`,
  `1e21` → `1e+21`, `1e20` → `100000000000000000000`, `1e-7` → `1e-7`, `1e-6` → `0.000001`); an integer literal is read
  as the nearest double (`9007199254740993` → `9007199254740992`);
- refused (`DP-ENG-016`): NaN, ±Infinity (including literals that overflow, such as `1e400`), lone surrogates,
  `undefined`, functions, sparse arrays and any non-plain object (Date, Map, class instances; tuples, sets and
  non-string keys in Python).

The record digest reported by a validator (`engineeringDecision(...).digest`, `decide(...)["digest"]`) is the
`datapass-c14n/1` digest of the whole record.

## Kinds

### `artifact-ref`

`id` (artifact id), `sha256` (exact bytes), `mediaType`, `bytes`, `scope` `public` | `private`, optional `locator`.
The locator is **opaque and private**: Studio never resolves, fetches or displays it. A reference proves only which bytes
were meant; it is not an access grant or a publication approval.

### `run-receipt`

`runId`, `inputDigest`, `code` `{version, commit?}`, `model` `{id, version, resolved?, reason?}`, `status`,
`cancelRequested`, `times` `{submittedAt, startedAt, finishedAt}` (UTC `YYYY-MM-DDTHH:MM:SS.sssZ` or null), `checks`
`{performed[], notPerformed[]}`, `coverage` `{consumed[], ignored[], fixed[]}`, `artifacts` (embedded `artifact-ref`
records) and `diagnostics` `[{code, severity, message}]`.

- `status` takes the runtime/1 values `queued | running | succeeded | failed | cancelled`; the set is closed.
  `cancelRequested` is the additive flag below. A cancelled run has `cancelRequested: true`; a running run may have it
  too (cancel requested, not yet observed).
- `model.resolved` is the provider's resolved variant/version. When the provider does not expose one, `resolved` is
  `null` **with** a `reason`; unknown metadata is never invented.
- `checks` and `coverage` lists are disjoint: a computation cannot claim a variable it ignored or fixed, and a check is
  either performed or not. Raw process success is not domain validation.

### `selection-binding`

`entityId`, `geometryRevision` (digest), `viewToken`, `bindings` `[{signal, entityId|null, status, source?}]`, optional
`timeCursor` (seconds).

- `viewToken` is an opaque view identity. It is **not an authorization token** and grants nothing.
- Binding status: `sourced` (entity and source named), `inferred` (entity named, e.g. by a name match), `unmapped`
  (no entity, no source).
- **`unmapped` never animates.** **`inferred` animates only after an explicit consumer opt-in** and is shown as
  inferred. Selection, camera and time cursor are view state: they never change a design revision or its digest.

### `approval-request`

`purpose`, `baseRevision`, `proposalDigest`, `requester`, `endpointHint`, `presentationOnly: true`.

This is a **presentation-only** request. Studio shows it and hands it to the domain service through a callback; it
**never issues, stores or checks an approval**. The record has no approval state: `approved`, `approval_status`,
`status`, `decision`, `grant`, `authorization`, `signature`, `token` and similar keys are refused (`DP-ENG-014`). The
domain service issues and verifies authorizations (actor from its own authenticated session, purpose, digests, expiry,
usage policy). `endpointHint` is an absolute path hint (no host, query or dot segments), never a URL Studio calls on its
own. `proposalDigest` is normally the `datapass-c14n/1` digest of the `parameter-diff` record it presents (see the corpus).

### `parameter-diff`

`baseRevision` (digest of the exact base) and `changes` `[{id, unit, from, to, consumedBy[]}]` (1 to 1000).

- `unit` is **required**; `""` means dimensionless. Units are compared as strings; an adapter must normalize them.
- `from` / `to` are null, boolean, finite number or text. `from: null` adds a value, `to: null` removes it. A change
  that does not change the value (canonically equal, or both null) or switches the value type is refused.
- `consumedBy` lists the computations that read the parameter (possibly none).

## Frozen `datapass.runtime/1` additive wire

Later packages implement these; their shape is frozen here so consumers can rely on it. All are additive: a client
that ignores them keeps working.

1. **`Idempotency-Key` request header** on run submission (`POST /api/runtime/v1/runs`). Same key and same payload →
   the first run record is returned again (no new run). Same key and a different payload → **`409 Conflict`**. Keys
   are opaque client strings, kept in a bounded server-side window. CORS allows the header.
2. **`cancelRequested: boolean`** on every `RunRecord`, additive. Cancelling a running run sets it to `true` while
   `status` stays `running` until the model observes the cancel; the `RunStatus` set does not change.
3. **`GET /api/runtime/v1/ready`**, authenticated like every runtime/1 route, returns
   `{"live": boolean, "ready": boolean, "checks": [{"id": string, "ok": boolean, "detail": string}]}` (e.g. worker
   capacity, result store, optional notebook support with the reason it is unavailable). `/health` stays a minimal
   liveness probe.

## Mapping from `foilai.design-change/1`

The FOIL AI lane emits design-change proposals carrying `base_revision` (sha256), typed `from` / `to` values with units
and `approval_status = PENDING`. A **consumer adapter** (in the consumer repository, not in Studio) maps one proposal to:

- a `parameter-diff`: `baseRevision = {alg: "sha256", over: <what the producer hashed>, value: base_revision}`, one
  change per typed parameter with its unit (`""` when dimensionless), `from` / `to` unchanged, `consumedBy` from the
  model's coverage;
- an `approval-request`: `baseRevision` as above, `proposalDigest = digest(parameter-diff)`, `presentationOnly: true`.
  `approval_status` is **not** carried over: approval state lives only in the domain service (a record that carries it
  is refused, see `invalid/a-approval-status.json`).

Ambiguous units, unknown parameter ids or non-finite values are rejected by the adapter before mapping.

## Vendoring

Consumers on an older framework snapshot (for example a 0.8.1 copy) do not need the rest of Studio:

1. Copy, at one pinned commit of this repository: `src/framework/engineering/contract.ts` (no imports, no
   dependencies), `spec/engineering/v1/engineering.schema.json`, and `tests/fixtures/engineering/` (with `.gitattributes`
   `-text` for that folder so line endings stay byte-exact). Python consumers copy `py/datapass_engineering.py`.
2. Record the commit and the sha256 of each copied file.
3. Verify with the corpus: every `manifest.json` fixture must give the same decision, `code` and `where`; every c14n
   vector the same bytes and sha256 (`tests/engineering.test.mjs` and `py/test_datapass_engineering.py` show how).
4. Never edit the copy. A new rule means a new contract version.

The legacy fixture `legacy-0.8.1/wind-aep-weibull.json` is a byte copy of the 0.8.1 reference artifact; the corpus
asserts that an `artifact-ref` with its exact sha256 is valid and that the current `datapass.artifact/1` validators still
accept it.

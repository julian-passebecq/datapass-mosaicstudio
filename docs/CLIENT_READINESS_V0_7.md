## What changed from v0.6

The prior biggest generic gap for the separate product-teardown experience was the lack of an imported ModelAsset path. v0.7 closes the first useful version of that gap without broadening Studio into a CAD/game engine.

The remaining common high-value framework work is now more concentrated: D3/VizForge choreography and annotation polish, SemanticOverlay where a real client proves it necessary, public/accessibility/performance hardening, stable API/migration policy, and the five thin client acceptance slices.

## Boundaries

The new static model profile does not validate scientific meaning, licensing or measurements. Run history remains in-memory unless an approved provider is added. Static knowledge is not RAG. Semantic navigation is not automatic graph layout. Publication metadata is not authentication or deployment.

Do not make Galaxy use imported 3D when 2D/isometric/DAG communicates the data more clearly. Do not make the portfolio spatial merely because Galaxy is spatial. Foil'o engineering and product teardown can share approved assets and semantic IDs while remaining distinct experiences.

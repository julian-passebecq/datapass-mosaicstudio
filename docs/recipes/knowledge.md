# Knowledge family

Use `--family knowledge`. One client-owned `ExplorerSpec` provides items, parents, facets and documents. `explorerFields` and `explorerBlock` provide the coherent view state.

The default is a searchable library with an optional 2D relationship map. No 3D resource or renderer is necessary. Keep capability, company, project, maintenance or evidence labels in client content rather than hardcoding them into the framework.

Selecting an object focuses it. Opening a project is a separate declared action. Changes across focus/facet/domain/document must be made atomically with the explorer helpers. Saved inputs are validated before any change.

Filters and L1/L2/L3 are presentation modes, not access control. A view link contains IDs, not confidential document bodies; the site must already have approved content.

Add `architecture` only for an artifact-backed system/schema review. Do not import the old DiagramCloud or notebook UI. Add a spatial resource later only when it adds value; the same selected identity then survives across all three views.

Detailed contract, only when needed: `docs/EXPERIENCE_KIT.md`.
